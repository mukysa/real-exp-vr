实现细则：

- 第一版复用现有 `solve_fr3_ik()`，关闭多种子搜索，缓存模型；候选解只有通过检查后才更新上一帧目标及种子。
- 求解核心不创建 ROS 节点或通信；ROS description/xacro 仅用于初始化模型，不复制另一套运动学定义。
- 使用固定时间步长、平滑起停轨迹；平移在机器人基坐标系中定义，旋转明确采用基坐标轴还是工具局部轴。
- 关节速度和加速度按轨迹时间计算；正常跟随段与故障切换段分开统计。
- 先实现静止、XYZ 单轴往返、小角度旋转和异常注入，再增加小圆与平移旋转组合。
- 迭代预算不是硬时间截止；求解返回后拒绝超时结果不能宣称为有界实时求解。

确定性与性能分开验收：固定输入、种子、迭代预算和轨迹时间的回放应产生一致的目标及状态；实际 wall-clock 耗时单独统计，不要求耗时字段逐字一致。性能测试先预热，报告 P50/P95/P99、最大耗时与周期超限数。若启用墙钟截止决定接受/拒绝，标记为性能/在线策略测试，不与确定性轨迹验收混淆。

每次运行写入独立目录：`samples.jsonl` 保存目标、候选解、检查通过目标、状态、残差、耗时与原因；`summary.json` 保存配置、模型标识和统计；`report.html` 内嵌末端轨迹、七关节、速度/加速度、误差和耗时的交互式曲线，无需额外绘图依赖。

现有优化 IK 可作为基线，但默认多种子搜索和较多迭代不能直接视为满足在线预算。根据测量结果决定是否采用有明确计算预算的局部迭代 IK。例如选择 50 Hz 时，需要为整个计算和通信链保留 20 ms 周期预算。

## 与 VR 采集侧的接口约定

优先沿用现有 `ReceivedPose` 和 `TargetPose`，避免另建重复协议。

| 接口项 | 必须明确的内容 |
|---|---|
| 位姿 | 位置单位为米；四元数顺序明确，例如 `xyzw` |
| 坐标系 | 原始 OpenVR、现有 Unity 合约或转换后的机器人坐标，不能混用 |
| 时间与来源 | 接收时间、连接标识；设备时间与 PC 轮询时间分开描述 |
| 有效性 | 跟踪有效、断流、重连如何表达 |
| 接管按钮 | 按下/松开状态、边沿及接管语义 |
| 控制状态 | 跟随、正常保持、故障保持及原因 |

IK 层接收经坐标转换和安全状态机处理的目标，不能只传位置与四元数而丢失控制状态。
